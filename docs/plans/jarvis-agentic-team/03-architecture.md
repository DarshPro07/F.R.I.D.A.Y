# 03 — Architecture

## Current architecture (relevant parts)
- Voice paths: LiveKit agent (`agent_friday.py`, Sarvam/Deepgram → Gemini → OpenAI TTS)
  and the control room (`friday/ui_server.py` → `friday/voice_brain.py`, Gemini with
  one `use_capability` tool whose menu is derived from `fabric.registry()`).
- Execution: `friday/hermes_bridge.py` (`HermesSupervisor`, durable `WorkRunLog`,
  delivery broker) behind `friday/executors/hermes.py`; `execution_economics.plan_delegation`
  picks tier → model → reasoning effort.
- Memory: six tiers in `friday/memory_stack.py` over `friday/store.py` (SQLite) and the
  vault; `brain.SharedBrainAdapter` (GBrain) with a secret-shape guard; `TaskBundle.with_memory()`
  compiles 600 tokens of it into each Hermes bundle.
- Objective engine: `friday/continuity.py` (runs, portions, budgets, wakes) driven by
  `friday/continuity_livekit.py`; `ui_server._metrics/_objective` render it.
- Third-party code: the capability fabric (`friday/fabric.py`), one adapter per upstream in
  `friday/fabric_adapters/`, skill packs via `_skillpack.py`; pins in `third_party/UPSTREAM_LOCK.json`.
- Organisation: `friday/org.py` reads divisions from `third_party/upstream/agency-agents`.

## Proposed fit (no new registries, no new services)
| Need | Where it lands | Why there |
|---|---|---|
| Hermes result → shared memory | one terminal-status choke point in `hermes_bridge.py`, writing through existing `store` / `memory_stack.log_result` / `brain` APIs | the bridge already owns the run lifecycle and the delivery broker; memory tiers already exist |
| Portion token cap | `continuity.record_model_tokens` / `record_actions` mark exhaustion; `continuity_livekit` checkpoints on it; `remaining_budget()` for pre-call sizing | the budget objects and counters already exist; only enforcement timing is missing |
| Honest header | `ui_server._metrics` scoped to the current objective + `all_time` block; `ui/index.html` labels | the data is already there, only the aggregation scope is wrong |
| Packs for Friday | two SKILL providers in `fabric_adapters/` (roles family) + `org.py` loading VoltAgent categories as divisions | identical to `company_playbooks` / `role_recipes`; the lock enforces pins and licences |
| Packs for the owner | `~/.claude/agents/` (VoltAgent, model set per role), agents-team as a Claude Code plugin, this repo's `.claude/` team generated by the pack's own `scaffold.py` and graded by its `lint.py` | the packs are Claude Code tooling; using their generator is the point |

## Data flow (new pieces)
1. Hermes run reaches COMPLETE/PARTIAL/FAILED → `on_terminal(record)` → sanitized outcome
   (goal, status, model, route, ≤600-char summary, work_run_id) → store (message on the
   voice-brain conversation + a durable outcome row/observation) → vault log →
   readable by `memory_stack.aggregate(..., include_episodes=False)` (Hermes bundles)
   and by `voice_brain._memory_context` / `_recent_turns` (next turn).
2. LiveKit usage event → `record_model_tokens(claim, delta)` → counters → if portion or
   run budget crossed: event `budget_exhausted`, claim marked exhausted → `continuity_livekit`
   checkpoints with the reason and stops admitting actions for that portion; run-level →
   `_finish_budget` immediately.
3. `/api/state` → `_metrics` → `{open_tasks, model_tokens}` for the run in `_objective`
   plus `all_time: {...}` → header shows "this objective" and "all-time".
4. `roles/catalogue|search|recipe` (VoltAgent) and `roles/archetypes|rules|read` (agents-team)
   → `_skillpack.read` (allowlisted) → spoken answer in role.

## Interfaces / contracts
- `hermes_bridge`: `on_terminal(record: dict) -> None`, never raises; idempotent per `work_run_id`.
- `continuity`: `RunSnapshot` gains `budget_exhausted: str` ("" | "portion:model_tokens" | "run:actions" ...);
  `remaining_budget(claim) -> dict(portion={...}, run={...})`.
- `ui_server._metrics(conn, run_id)`: current keys keep their names but are scoped to `run_id`;
  new key `all_time`. Playwright `happy-path.spec.ts` envelope test must still pass.
- Fabric descriptors: `family="roles"`, `mode=SKILL`, `license="MIT"`, `commit=<pinned sha>`,
  `open_operations` declared so `voice_brain._surface()` exposes the read ops.

## Failure paths
Absent clone → provider UNAVAILABLE, boot unaffected. Memory write fails → logged, the
delivery still speaks. Budget exhaustion → checkpoint + wake, never a crash. Plugin
install fails → documented manual command; the generated `.claude/` team still works.

## Security
Outcome text passes `brain._sensitive` before any write (no secrets in memory).
Skill packs read only catalogue entries (no path traversal). Hooks that could block
or mutate are staged, not wired. No new network egress.

## Observability
`run_events` rows for `budget_exhausted`; `hermes_work_runs` unchanged; latency notes
unchanged; `lint.py` grades recorded in `team.md`.

## Compatibility
Additive schema only (`CREATE TABLE IF NOT EXISTS` / new columns via `_ADDED_COLUMNS`
pattern). `/api/state` keys preserved. Existing 41 upstream pins untouched.

## Alternatives considered
- A new "outcomes" memory service: rejected, duplicate memory (NON_NEGOTIABLE 11).
- Capping the LiveKit LLM globally: rejected, punishes every turn for the objective engine's fault.
- Copying the packs into `friday/`: rejected, they are pinned upstreams like the other 41.

## Risks
The choke point in `hermes_bridge` may be several sites (event handler, poll, wait
path); missing one leaves a silent gap. Budget enforcement inside the LiveKit turn
can only stop the next action, not the in-flight model call. Plugin install is a
CLI whose non-interactive behaviour on Windows is unverified.
